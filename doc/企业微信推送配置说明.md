# 企业微信推送配置说明

## 功能与入口

平台管理员通过「系统管理 → 企业微信推送」管理一份平台级配置，将多个项目的任务汇总到一个企业微信群。前端菜单模式与后端菜单模式均提供此入口，接口同时校验平台管理员身份。

- 日报：周一至周五在所选时间推送，周六、周日跳过。
- 未来一周提醒：周一至周五在所选时间推送，周六、周日跳过。
- 时间通过弹窗勾选，所选时间全部以换行标签展示。时间点支持多选，范围为 `00:00` 至 `23:30`，间隔半小时，统一使用北京时间 `Asia/Shanghai`。
- 项目通过弹窗搜索、多选，支持全选搜索结果和清空全部；确认后才更新表单，取消保留原选择。已归档、已删除项目不会出现在候选列表或新报告中。
- 支持消息预览、手动推送、最近 30 次发送记录和分片发送进度。

## 统计口径

平台总览统计所选未归档、未删除项目的全部未删除任务，包含历史已完成任务、未来到期任务以及无截止日期任务。该范围不受当前登录用户或任务负责人的限制。

总任务、已完成、处理中、未开始按任务当前状态统计；完成率为已完成数除以总任务数。已逾期指截止时间严格早于统计时间且未完成的任务，是未完成任务的子集，不额外计入总任务。无截止日期任务保留在平台总览和未完成总数中，不进入提醒明细。

日报另外列出当天 `00:00` 至次日 `00:00` 到期任务的数量和当前状态；周报另外列出从推送时刻起至 7 天后同一时刻到期任务的数量和当前状态，包含两个边界时刻。到期统计不代表该时段内新增或完成任务数量。

日报明细仅展示今天到期及历史逾期的未完成任务，次日及更晚到期的任务不展示。周报明细仅展示从推送时刻起未来 7 天内到期的未完成任务，超过 7 天或早于推送时刻截止的任务不展示；历史逾期任务由日报提醒。两种明细均排除无截止日期任务。按截止时间升序排列；截止时间相同时按优先级降序、任务 ID 升序排列。负责人仅包含任务执行者，多名执行者合并展示，不包含关注者；未分配执行者显示「未分配」。优先级沿用看板的普通、紧急、非常紧急。

明细列：序号、项目名称、任务标题、负责人、优先级、任务状态、截止时间、到期提示。到期提示区分逾期天数、今日已逾期、今日到期、明日到期和剩余天数，天数按北京时间的自然日计算。

当日没有到期任务时，日报仍显示平台总览和历史逾期任务。日报没有符合范围的明细时显示「暂无今日到期或历史逾期的未完成任务」，周报显示「暂无未来7天内到期的未完成任务」，不会将范围外的未完成任务误报为已完成。全部任务已完成时显示明确提示；所选项目没有任务时显示「所选未归档项目暂无任务」。

## 一、创建企业微信群消息推送

1. 在企业微信中打开目标群，进入群设置，查找「消息推送」（原「群机器人」）。不同客户端的入口名称可能不同。
2. 创建一个用于 TeamSync 任务提醒的消息推送。
3. 在创建完成页或消息推送详情页复制 Webhook。地址格式为 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...`。
4. 将该地址填入系统配置页。地址属于发送凭证，避免提交到版本库或公开分享。

接入采用群消息推送 Webhook，无需开发企业自建应用，也无需在 TeamSync 配置企业 ID、AgentId 或应用 Secret。若目标群没有消息推送入口，应先向企业微信管理员确认该群是否具备此能力。

接口格式、客户端兼容范围和限制见[企业微信官方消息推送配置说明](https://developer.work.weixin.qq.com/document/path/91770)。系统使用 `markdown_v2` 表格；较旧客户端可能显示为纯文本，建议更新客户端。

## 二、执行数据库增量脚本

在与后端连接相同的 PostgreSQL 数据库中执行 `doc/sql/wecom_push.sql`。目标数据库需要已有 `teamsync` schema 和业务表。

可以通过数据库管理工具打开并执行整个脚本，或在项目根目录运行以下命令，替换连接参数：

```bash
psql -h "数据库地址" -p 5432 -U "数据库账号" -d "数据库名称" \
  -v ON_ERROR_STOP=1 -f "doc/sql/wecom_push.sql"
```

脚本只新增配置表 `sys_wecom_push_setting` 和队列表 `sys_wecom_push_job`，不会修改已有任务、项目或账号数据。脚本支持重复执行。执行账号需要建表权限，后端运行账号需要新表的读写权限和队列主键序列的使用权限。

不要将 JDBC 格式的 `DB_URL` 直接传给 `psql`；两者连接串格式不同。

## 三、设置服务端环境变量

首次配置时，在服务器上创建一个 32 字节随机密钥，保存为 Base64 文本；例如使用 OpenSSL：

```bash
openssl rand -base64 32
```

将结果保存在部署平台的密钥配置或服务器受限环境文件中，并为后端进程配置：

```bash
export TEAMSYNC_WECOM_ENCRYPTION_KEY='替换为上一步的 Base64 密钥'
export TEAMSYNC_WECOM_ENABLED=true
```

然后重新构建、部署并启动后端，同时部署新版前端。通过项目脚本运行时，可在配置环境变量后的同一终端执行：

```bash
"./scripts/start-backend.sh" restart
```

Docker 或 NAS 容器部署时，应在后端容器的持久化环境配置中设置这两个变量，再重建或重启容器。仅在容器内临时 `export` 不会影响已经运行的后端进程，也不会在容器重建后保留。

`TEAMSYNC_WECOM_ENABLED` 默认 `false`，未完成部署配置时不会主动查询推送队列或发送消息。开启后，服务端需能通过 HTTPS 访问 `qyapi.weixin.qq.com:443`；这是出站请求，不需要对公网开放后端端口，也不需要回调域名。

Webhook 使用 AES-256-GCM 加密存入数据库。所有后端实例需要使用同一个密钥，并在重启、更新和迁移时保留它。更换密钥后，旧密文无法解密，需要重新保存 Webhook；旧队列快照也无法使用新密钥解密。

## 四、保存配置并验证

1. 使用平台管理员账号登录，打开「系统管理 → 企业微信推送」。
2. 填写群消息推送 Webhook，点击「选择项目」，在弹窗中搜索、勾选并确认。
3. 分别启用日报、未来一周提醒，点击「选择时间」勾选时间点并确认，再保存配置。两类推送均在周一至周五执行，周末跳过。已配置 Webhook 时输入框留空会保留原地址，输入新地址会替换。
4. 选择日报或周报，点击「预览消息」，核对汇总、未完成明细和实际消息文本。
5. 点击「推送到群」加入发送队列。此操作会发送真实任务信息，无需等待定时点。
6. 观察「最近发送记录」中的状态和成功条数，并核对企业微信群内消息。

预览和手动推送使用已保存配置。修改配置后需要先保存；手动推送不受日报、周报各自定时开关限制，但需要服务端总开关开启。

## 发送行为与故障处理

- 每 15 秒扫描一次当前分钟；仅在整点、半点所选时间入队。同一报告类型和时间点使用数据库唯一键去重。
- 每条 `markdown_v2` 消息不超过 4096 个 UTF-8 字节，超长列表按完整任务行分片，每片重复汇总和表头。全部任务均保留，过长的单个字段会缩短显示：项目名称最多 60 个字符、标题 200 个字符、负责人 150 个字符。
- 队列通过数据库行锁协调多个实例，全平台每 3.5 秒最多开始发送一条消息，低于企业微信每分钟 20 条的上限。其他系统若共用同一 Webhook，仍会共同占用企业微信的发送额度。
- 成功发送一个分片后立即保存进度。后端重启后，尚未领取的分片可继续发送。
- 已领取但两分钟内未确认结果的分片会标记失败；网络失败、超时、企业微信业务错误也会记录失败，不自动重复发送。确认群内实际收到的消息后，可手动推送新的报告；新报告会重新发送全部分片。
- 停机期间错过的时间点不会在恢复后批量补发；可使用手动推送。定时点生成的报告为入队时快照，之后的任务或配置变更不会改写已入队的消息。
- 日报、周报开关控制后续定时入队；已入队消息继续发送。服务端总开关关闭后停止扫描和发送，重新开启会继续处理原有待发送队列。
- 页面仅展示最近 30 次记录，数据库会保留历史记录和报告快照，可按企业的数据保留政策另行维护。

常见问题：

| 现象 | 处理方式 |
| --- | --- |
| 配置页提示数据库访问失败 | 确认脚本已在后端实际使用的数据库执行，且账号具备新表与序列权限 |
| 页面提示加密密钥未配置 | 设置合法的 Base64 编码 32 字节密钥并重启后端 |
| 页面提示服务端未开启推送 | 设置 `TEAMSYNC_WECOM_ENABLED=true` 并重启后端 |
| Webhook 解密失败 | 核对所有实例的密钥是否一致；恢复原密钥或重新保存 Webhook |
| 企业微信返回错误码 | 根据官方文档核对 Webhook、消息推送状态及发送额度 |
| 请求失败或超时 | 确认后端服务器的 DNS、HTTPS 出站访问和部署环境代理，再核对群内是否已经收到消息 |
| 报告为空 | 核对所选项目是否存在未删除任务，以及项目是否被归档；无截止日期任务纳入平台总览，但不会进入提醒明细 |

## 开发验证入口

后端单元测试与前端构建：

```bash
cd "TeamSync"
"./mvnw" -Dtest="Wecom*Test" test
cd "../TeamSync_web"
pnpm build:prod
```

数据库集成测试需要独立、可清空的本机测试数据库：数据库名和账号均为 `wecom_test`，通过环境变量显式开启。该测试会清空测试库内使用的同名表，禁止指向业务数据库；未设置变量时默认跳过。

```bash
cd "TeamSync"
TEAMSYNC_WECOM_TEST_DB_URL="jdbc:postgresql://127.0.0.1:55439/wecom_test" \
  "./mvnw" "-DsocksNonProxyHosts=localhost|127.*|[::1]" -Dtest="Wecom*Test" test
```

测试覆盖平台全量统计、日报仅含今日到期及历史逾期、周报未来 7 天边界及范围外排除、无截止日期任务仅计入总览、历史逾期、归档和删除过滤、多负责人、UTF-8 分片、密钥和地址校验、平台管理员权限、周一至周五双类型定时、周末跳过、独立时间与开关、唯一键去重、分片进度、异常结果和并发限速。HTTP 测试使用模拟响应，不向真实企业微信群发送消息。
