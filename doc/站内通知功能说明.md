# 站内通知功能说明

本文档记录 TeamSync 站内通知中心的功能范围、入口、接口和前端路由维护口径。

## 功能范围

站内通知统一写入 `sys_notification`，不复用 `pm_task_reminder_log`。当前通知类型包括：

- `TASK_DUE`：任务即将到期
- `TASK_OVERDUE`：任务已逾期
- `TASK_COMPLETED`：任务从非完成状态切换为已完成
- `RECURRING_PLAN_DUE`：周期计划到期
- `RECURRING_PLAN_OVERDUE`：周期计划已逾期
- `PROJECT_MEMBER_JOINED`：被加入项目
- `PROJECT_MEMBER_ROLE_UPDATED`：项目角色调整
- `PROJECT_MEMBER_REMOVED`：被移出项目
- `PROJECT_MEMBER_QUIT`：成员主动退出项目，通知项目拥有者

## 前端入口

- 顶部栏铃铛按钮：打开通知下拉，显示最近通知、未读数、待办分类、全部已读和点击跳转。
- 通知下拉底部 `查看全部通知`：跳转 `/user/notifications`。
- 个人中心：有 `站内通知中心` 按钮，跳转 `/user/notifications`。
- 完整通知页 `/user/notifications`：支持类型筛选、仅未读筛选、单条已读、选中批量已读、全部已读、刷新和 `去处理` 跳转。

## 后端接口

- `GET /api/notifications`：分页查询当前用户通知，支持类型和未读过滤。
- `GET /api/notifications/unread-count`：查询当前用户未读数。
- `PUT /api/notifications/{id}/read`：单条已读。
- `PUT /api/notifications/read`：批量已读。
- `PUT /api/notifications/read-all`：全部已读。

WebSocket/STOMP 主题为 `/topic/notifications/{userId}`。后端只推送未读数刷新信号，前端收到后重新拉取通知列表。

## 去重和数据边界

- `sys_notification.user_id + dedupe_key` 做唯一去重，同一用户同一业务窗口不会重复刷屏。
- `TASK_COMPLETED` 的去重窗口使用本次完成操作时间；同一次完成操作不会重复生成通知，任务重新打开后再次完成允许再次通知。
- 任务完成通知收件人来自任务关注人、任务创建人和项目拥有者，统一去重并排除本次操作人。
- 任务提醒邮件仍使用 `pm_task_reminder_log` 做发信去重，站内通知不承担邮件去重。
- 周期计划只接入站内通知调用点，没有改变计划生成、完成、跳过、延期的核心推进逻辑。

## 前端路由维护口径

当前前端路由入口和模块文件使用 `TeamSync_web/src/router/**/*.js`。同目录同名 `.ts` 路由文件不会进入当前路由解析链路，后续新增、删除或调整路由时必须修改 `.js` 文件。

本次已将 `TeamSync_web/src/router` 下原有同名 `.ts` 路由文件备份到 `doc/router-ts-backup-20260608.tar` 后从源码目录删除，避免后续误改无效文件。接口封装和业务组件的 `.ts` 文件不属于这次删除范围。
