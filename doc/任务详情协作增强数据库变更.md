# 任务详情协作增强数据库变更

更新时间：2026-06-08

## 执行状态

已对当前 `application.yml` 配置的数据源执行本文件 DDL，并通过元数据查询确认：

- `teamsync.pm_file_node.task_id` 存在
- `teamsync.idx_file_task_id` 存在

## 变更摘要

本阶段为任务详情补充附件关联能力，新增文件节点到任务的可空关联字段。责任人和关注人/参与人不新增表，复用已有 `pm_task_member`：

- `role = 'EXECUTOR'`：任务负责人
- `role = 'FOLLOWER'`：任务关注人/参与人

## DDL

```sql
ALTER TABLE teamsync.pm_file_node
    ADD COLUMN IF NOT EXISTS task_id bigint;

COMMENT ON COLUMN teamsync.pm_file_node.task_id IS '关联任务ID，任务附件使用；项目文档为空';

CREATE INDEX IF NOT EXISTS idx_file_task_id
    ON teamsync.pm_file_node USING btree (task_id);

COMMENT ON COLUMN teamsync.pm_task_log.action_type
    IS '操作类型: CREATE/UPDATE/MOVE/DELETE/COMMENT/SUBTASK/ATTACHMENT';
```

## 字段说明

| 表 | 字段 | 说明 |
| --- | --- | --- |
| `pm_file_node` | `task_id` | 为空表示项目文档；非空表示任务附件，关联 `pm_task.id` |
| `pm_task_log` | `action_type` | 扩展日志类型说明，新增 `SUBTASK`、`ATTACHMENT` |

## 兼容性说明

- 历史项目文档的 `task_id` 默认为空，不影响原有文档目录结构。
- 项目文档列表会过滤 `task_id IS NULL`，任务附件不会混入项目文档根目录。
- 任务附件复用现有文件上传、下载、删除能力；删除附件会保留任务日志。
- 关注人/参与人复用 `pm_task_member`，不需要新增数据库字段。
