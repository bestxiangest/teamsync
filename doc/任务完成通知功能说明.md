# 任务完成通知功能说明

## 功能范围

本阶段新增任务完成通知能力：当看板任务状态从非完成状态切换为已完成时，系统生成 `TASK_COMPLETED` 站内通知，并在用户主动开启任务完成邮件提醒时发送邮件。

本阶段不新增任务关注者表，继续复用 `pm_task_member.role = 'FOLLOWER'`。

## 通知触发条件

- 后端入口：`PmTaskServiceImpl.updateTask`
- 触发条件：旧任务状态 `oldStatus != 1`，更新后的任务状态 `task.status == 1`
- 不触发场景：任务原本就是已完成、任务更新未切换到已完成、任务删除、任务创建

## 收件人规则

站内通知收件人包括：

- 任务关注人：`pm_task_member.role = 'FOLLOWER'`
- 任务创建人：`pm_task.creator_id`
- 项目拥有者：`pm_project.owner_id`

收件人统一去重，并排除本次操作人 `actorId`。

## 去重规则

- `sys_notification` 继续使用唯一约束 `user_id + dedupe_key`
- `TASK_COMPLETED` 的 `dedupe_key` 包含通知类型、任务 ID、收件人 ID 和本次完成操作时间
- 同一次完成操作重复调用不会重复生成站内通知
- 任务重新打开后再次完成时，完成操作时间不同，允许再次生成通知

## 邮件开关规则

邮件提醒默认关闭。本阶段新增个人设置字段：

- `sys_user_reminder_setting.task_completed_enabled boolean NOT NULL DEFAULT false`

只有同时满足以下条件才发送任务完成邮件：

- 用户已配置有效邮箱
- 用户开启邮件提醒总开关 `email_enabled`
- 用户开启任务完成邮件开关 `task_completed_enabled`
- 系统邮件提醒开关 `teamsync.mail.reminder.enabled` 为 true
- SMTP 邮件通道可用

发送失败只记录日志，不阻断任务更新和站内通知生成。

## 功能复现方式

1. 在个人中心填写邮箱，开启邮件提醒总开关；如需验证邮件，再开启任务完成提醒开关。
2. 在项目看板中创建或选择一个非完成状态任务。
3. 给任务添加关注人，并确认任务有创建人；项目存在 `owner_id`。
4. 使用非收件人用户或不同用户将任务状态从未完成/处理中改为已完成。
5. 查询或打开通知中心，确认相关用户生成 `TASK_COMPLETED` 通知，标题为 `任务已完成`，目标路径为 `/project/board/{projectId}`。
6. 如果收件人已开启任务完成邮件提醒，且 SMTP 通道可用，确认发送任务完成邮件。

可用 SQL 核查：

```sql
SELECT id, user_id, type, title, source_type, source_id, target_path, dedupe_key, actor_id, read_flag, created_at
FROM teamsync.sys_notification
WHERE type = 'TASK_COMPLETED'
ORDER BY created_at DESC, id DESC
LIMIT 20;
```
